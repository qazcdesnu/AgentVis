# 시스템 구조

이 문서는 AgentVis의 구성 요소, 데이터 흐름, 저장 구조, 기술 선택, 구현 순서를 정한다. 제품의 목적과 결정 사항은 [제품 비전](ProductVision.md)에, 원천 데이터의 상세는 [데이터 소스](DataSource.md)에 있다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## 1. 전체 구조

```text
Claude Code 세션
  ├─ http hook (POST JSON) ──────────▶ [수집기] ──(읽기 요청: transcript_path)──┐
  │                                       │                                   ▼
  └─ 세션 기록 파일 (JSONL) ──(이어 읽기)─────────────────────────────▶ [기록 리더]
                                          ▼                                   │
                                          └──────────────┬────────────────────┘
                                                         ▼
                                          [이벤트 저장소 (원시 이벤트)]
                                                     ▼
                                    [분석기] ──▶ [파생 모델: 세션·턴·도구 호출·신호]
                                                     ▼
                                          [API + 실시간 전송(SSE)]
                                                     ▼
                                             [웹 UI (브라우저)]
```

수집기부터 API까지는 하나의 로컬 서버 프로세스(AgentVis 서버) 안에서 동작한다. 두 데이터 소스의 역할은 [데이터 소스 개요](DataSource.md#1-개요)에 있다. hook은 "방금 이 세션에 무슨 일이 있었다"는 실시간 신호와 hook에만 있는 정보를, 세션 기록은 작업 내용의 주된 출처를 맡는다.

1. Claude Code는 [hook 이벤트](DataSource.md#2-hook-이벤트)를 AgentVis 서버로 POST한다.
2. **수집기**는 이벤트를 원시 그대로 이벤트 저장소에 넣고 즉시 응답한 뒤, 그 이벤트의 `transcript_path`를 기록 리더에 넘긴다.
3. **기록 리더**는 [세션 기록](DataSource.md#3-세션-기록-jsonl)을 마지막으로 읽은 위치부터 이어 읽어 같은 이벤트 저장소에 넣는다. 세션 기록은 작업하는 동안 실시간으로 쓰이므로, hook 이벤트가 올 때마다 이어 읽으면 사고 과정·작업 중 사용자 메시지까지 거의 실시간으로 들어온다.
4. **분석기**는 원시 이벤트로 세션·턴·도구 호출과 [진단 신호](ProductVision.md#3-진단-신호)를 계산한다.
5. **API**는 파생 모델을 웹 UI에 제공하고, 바뀐 내용을 실시간으로 밀어 준다.

## 2. 설계 원칙

- **원시 이벤트는 변경하지 않는다.** 들어온 이벤트는 받은 그대로 덧붙이기만 한다. 세션·턴·신호 같은 파생 모델은 언제든 원시 이벤트로부터 다시 계산할 수 있어야 한다. 판정 규칙이 바뀌면 다시 계산하면 된다.
- **Claude Code를 방해하지 않는다.** hook 수신은 저장만 하고 바로 응답한다. 분석은 응답 이후에 한다. 서버가 꺼져 있어도 Claude Code는 정상 동작한다([전달 방식](DataSource.md#21-전달-방식)).
- **내용은 세션 기록에서, 신호는 hook에서 얻는다.** 작업 내용의 대부분은 세션 기록에 있다. hook은 읽을 때를 알려 주고, hook에만 있는 정보를 더하며, 세션 기록 형식이 바뀌어 읽기에 실패할 때 최소한의 실시간 데이터를 보장하는 안전망이다.
- **유실은 세션 기록으로 메운다.** 서버가 꺼져 있던 동안의 작업은 세션 기록에 남아 있으므로 기록 리더가 채운다. 그래서 hook 전송은 재시도하지 않는다.
- **확정과 추정을 섞지 않는다.** 모든 신호는 확정·추정 구분과 근거 이벤트를 함께 가진다.
- **데이터는 로컬에만 둔다.** 서버는 `127.0.0.1`에만 바인딩하고, 같은 컴퓨터의 브라우저 웹페이지가 보내는 요청도 받지 않는다([요청 검증](design/Collector.md#21-요청-검증)). 외부 전송은 사용자가 켠 LLM 판정(2단계)뿐이다.

## 3. 구성 요소

| 구성 요소 | 책임 | 입력 → 출력 |
| --- | --- | --- |
| 수집기 | hook 이벤트 수신, 요청 검증, 원시 저장, 기록 리더에 읽기 요청 | HTTP POST → 원시 이벤트 |
| 기록 리더 | 세션 기록 파일(서브에이전트 기록 포함)을 마지막으로 읽은 위치부터 이어 읽기, 놓친 기록 찾기, 지난 세션 일괄 가져오기 | JSONL 파일 → 원시 이벤트 |
| 이벤트 저장소 | 원시 이벤트와 파생 모델 저장, 중복 제거 | — |
| 분석기 | 세션·턴·도구 호출 구성, 규칙 기반 신호 판정 | 원시 이벤트 → 파생 모델 |
| API·실시간 전송 | 조회 API, 변경 알림 스트림 | 파생 모델 → JSON, SSE |
| 웹 UI | 시각화와 탐색 | API → 화면 |
| CLI | 서버 실행, hook 설치·제거, 지난 세션 가져오기 | 명령 → 동작 |
| LLM 판정기 (2단계) | 지시 오해처럼 의미 해석이 필요한 신호 판정 | 턴 → 추정 신호 |

### 3.1 기록 리더가 실행되는 시점

상세는 [기록 리더 설계](design/Transcript.md)에 있다.

- **hook 이벤트를 받을 때마다**: 그 이벤트의 `transcript_path`(서브에이전트 이벤트는 그 서브에이전트의 기록 파일도)를 이어 읽는다. 응답을 보낸 뒤 서버 안의 별도 작업 스레드에서 읽는다.
- **서버가 시작될 때**: `~/.claude/projects/` 아래의 모든 세션 기록 파일 중 마지막으로 읽은 위치보다 커진 파일을 이어 읽는다. 서버가 꺼진 동안 시작하고 끝난 세션도 이렇게 찾는다.
- **사용자가 CLI로 지난 세션 가져오기를 실행할 때.**

## 4. 데이터 모델

### 4.1 원시 이벤트

| 필드 | 의미 |
| --- | --- |
| `id` | 이벤트 저장소 내부 일련번호 |
| `source` | `hook` 또는 `transcript` |
| `kind` | hook 이벤트 이름 또는 세션 기록의 `type` |
| `session_id`, `prompt_id`, `tool_use_id` | [결합 키](DataSource.md#1-개요). 없으면 비워 둔다. |
| `cwd` | 이벤트에 적힌 작업 디렉터리(절대 경로) 그대로. 없으면 비워 둔다. 프로젝트 판정은 파생 모델에서 한다. |
| `occurred_at` | 이벤트 발생 시각. hook 이벤트는 받은 시각, 세션 기록은 `timestamp`. |
| `dedup_key` | 세션 기록을 다시 읽을 때의 중복 제거 키. 규칙은 [기록 리더 설계](design/Transcript.md)에 있다. hook 이벤트는 POST 하나가 이벤트 하나이므로 비워 둔다. |
| `payload` | 받은 JSON 원문 |

### 4.2 파생 모델

| 모델 | 키 | 내용 |
| --- | --- | --- |
| 프로젝트 | 프로젝트 경로 | 세션들의 프로젝트 경로로 묶은 단위. 표시 이름(폴더 이름), 상위 경로, 세션 수, 마지막 활동 시각, 폴더 존재 여부 |
| 세션 | `session_id` | 프로젝트 경로(세션 기록의 첫 `cwd`. hook 이벤트의 `cwd`는 하위 폴더일 수 있어 쓰지 않는다 — [실측으로 확인한 동작](DataSource.md#25-실측으로-확인한-동작)), 시작·종료 시각, 상태(진행 중·종료) |
| 턴 | `prompt_id` | 사용자 지시 원문, 시작·종료 시각, 마지막 응답, 소속 세션 |
| 단계 | 원시 이벤트 `id` | 턴 안의 시간순 항목: 사고 과정, 응답 텍스트, 도구 호출, 사용자 개입, 문맥 압축 |
| 도구 호출 | `tool_use_id` | 도구 이름, 입력, 결과, 성공·실패, 오류 메시지, 소요 시간, 서브에이전트 여부 |
| 신호 | 일련번호 | 종류, 확정·추정, 근거 단계 목록, 설명 |

같은 사실이 hook과 세션 기록 양쪽에 있으면 결합 키로 하나로 합친다. 내용은 세션 기록을 우선하고, hook에만 있는 필드(도구 실행 시간, 권한 요청 등)를 보탠다. 세션 기록을 아직 읽지 못했거나 읽기에 실패한 부분은 hook 이벤트만으로 표시한다.

## 5. 외부 인터페이스

### 5.1 hook 설정

CLI의 hook 설치 명령이 Claude Code 사용자 설정(`~/.claude/settings.json`)에 아래 형태의 항목을 추가한다. 기존 설정은 보존하고, 바꾸기 전에 백업 파일을 남긴다. 제거 명령은 AgentVis가 추가한 항목만 지운다.

```json
{
  "hooks": {
    "PostToolUseFailure": [
      { "hooks": [ { "type": "http", "url": "http://127.0.0.1:8765/hooks", "timeout": 2 } ] }
    ]
  }
}
```

등록하는 이벤트는 [사용하는 이벤트](DataSource.md#23-사용하는-이벤트) 표의 전부다(`http` hook을 지원하지 않는 `SessionStart` 제외). 포트는 설정으로 바꿀 수 있다.

### 5.2 HTTP API

| 메서드·경로 | 용도 |
| --- | --- |
| `POST /hooks` | hook 이벤트 수신. 저장 후 즉시 `200` 응답. |
| `GET /api/projects` | 프로젝트 목록. 마지막 활동이 최근인 것부터. |
| `GET /api/sessions?project=<프로젝트 경로>` | 선택한 프로젝트의 세션 목록 |
| `GET /api/sessions/{session_id}` | 세션의 턴·단계·도구 호출·신호 |
| `GET /api/stats?project=<프로젝트 경로>` | 프로젝트 안에서 세션을 가로지르는 실패 유형 통계 |
| `GET /api/stream` | 변경 알림 SSE 스트림. 바뀐 세션·턴의 식별자를 보낸다. |
| `GET /` | 웹 UI 정적 파일 |

## 6. 기술 선택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어·환경 | Python 3.12, uv | [코드 작업 규칙](CodeRule.md#3-언어와-스타일) |
| 웹 서버 | FastAPI + uvicorn | 비동기 처리와 SSE 응답이 간단하고 널리 쓰인다. |
| 이벤트 저장소 | SQLite (표준 라이브러리 `sqlite3`) | 설치가 필요 없고 로컬 단일 사용자에 충분하다. |
| 실시간 전송 | SSE (Server-Sent Events) | 서버 → 브라우저 단방향이면 충분하고 WebSocket보다 단순하다. |
| 웹 UI | 빌드 단계 없는 정적 HTML·JS | 초기 단계에서 도구 체인을 늘리지 않는다. 시각화 라이브러리는 UI 설계 문서에서 정한다. |

데이터 디렉터리는 `~/.agentvis/`이며 SQLite 파일(`agentvis.db`)과 hook 설정 백업을 둔다.

## 7. 코드 구성

제품 코드는 `src/agentvis/` 패키지에 둔다. 실행 명령은 `uv run agentvis <하위 명령>`이다(`pyproject.toml`의 `[project.scripts]`).

| 모듈 | 구성 요소 | 상세 설계 |
| --- | --- | --- |
| `agentvis/cli.py` | CLI (`serve`, `hooks install`, `hooks uninstall`, `import`) | [CLI 설계](design/Cli.md) |
| `agentvis/hook_settings.py` | Claude Code 설정 파일의 hook 추가·제거 | [CLI 설계](design/Cli.md#3-hook-설정-편집) |
| `agentvis/server.py` | FastAPI 앱, HTTP API, SSE | [수집기 설계](design/Collector.md#2-http-엔드포인트) (M1 범위) |
| `agentvis/collector.py` | 수집기 | [수집기 설계](design/Collector.md) |
| `agentvis/transcript.py` | 기록 리더 | [기록 리더 설계](design/Transcript.md) |
| `agentvis/store.py` | 이벤트 저장소 | [이벤트 저장소 설계](design/Store.md) |
| `agentvis/analysis/` | 분석기 (모델 구성, 신호 규칙) | M3-T1에서 작성 |
| `agentvis/web/` | 웹 UI 정적 파일 | M4-T1에서 작성 |

각 구성 요소는 구현에 들어가기 전에 상세 설계 문서를 먼저 작성하고, 그 문서에서 [포인터 규약](Traceability.md)에 따라 구현할 심볼을 가리킨다. 이 문서는 구조만 정하므로 코드 포인터를 두지 않는다.

## 8. 구현 순서

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| M1 | 이벤트 저장소, 수집기, CLI(`serve`, `hooks install/uninstall`) | 실제 Claude Code 세션의 hook 이벤트가 이벤트 저장소에 쌓인다. |
| M2 | 기록 리더, 지난 세션 가져오기 | 진행 중인 세션의 사고 과정·작업 중 사용자 메시지가 hook 이벤트와 함께 거의 실시간으로 쌓이고, 서버를 끈 채 진행한 세션도 서버 시작 후 채워진다. |
| M3 | 분석기: 세션·턴·도구 호출 구성, 확정 신호 | API로 턴별 과정과 실패 지점이 조회된다. (Q1~Q3) |
| M4 | 웹 UI 실시간 보기 | 프로젝트를 선택하면 그 프로젝트의 진행 중인 세션의 과정과 실패가 화면에 실시간으로 나타난다. |
| M5 | 추정 신호 규칙: 반복 실패, fallback, 정정 | Q4~Q6에 대한 표시가 근거와 함께 나타난다. |
| M6 | 통계 화면 | 세션을 가로지르는 실패 유형 통계가 보인다. |
| M7 | LLM 판정 (선택 기능) | 사용자가 켜면 지시 오해 판정이 추가된다. |

각 단계는 해당 상세 설계 문서 작성 → 구현 → [검증 도구](VerificationTools.md) 통과 순서로 진행한다. 단계별 태스크와 진행 상태는 [로드맵](Roadmap.md)에 있다.
