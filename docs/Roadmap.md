# 로드맵

이 문서는 AgentVis의 할 일을 마일스톤(M)과 태스크(T)로 나눈 목록이다. 각 태스크는 한 줄로 무엇을 할지만 적는다. ID와 상태 표기, 작업 흐름은 [작업 관리 규칙](TaskRule.md)을 따르고, 진행 중인 작업의 상세는 [진행 중](Ongoing.md)에, 끝난 작업의 상세는 [완료](Done.md)에 있다. 마일스톤의 목표와 완료 기준은 [시스템 구조](Architecture.md#8-구현-순서)에 있다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

**우선 진행 순서** (2026-10-31 사용자 결정): 화면을 보면서 개발할 수 있도록 첫 화면에 필요한 태스크를 먼저 한다. M3-T1 → M3-T2 → M3-T4 → M3-T5 → M4-T1 → M4-T3. 이어서 작업 흐름 그래프(I24)를 한다: M4-T6 → M4-T7 → M4-T8. 나머지 태스크는 그 뒤에 ID 순서로 한다.

**과업 중심 화면 우선** (2026-11-01 사용자 결정, I32): 유저 스터디에 쓸 화면을 먼저 만든다. M8을 M8-T1부터 차례로 하고, M8 태스크가 필요로 하는 판정 규칙(M5)은 그 태스크 안에서 함께 설계한다.

**수업 실험의 T1·T2는 식별 과업** (2026-11-09 사용자 결정, I57): 유저 스터디 기준판(1.1.0) 전에는 M8-T6(완료 보고와 테스트 사건 표시)을 M8-T2보다 먼저 한다. M8-T2의 T1·T2 구성(주장 ↔ 근거, 실패 → 변경의 판정 연결)은 제출용 실험(1.2)에 쓴다.

**유저 스터디 기준판 1.1.0의 범위** (2026-11-12 사용자 결정, I58): 수업 실험의 T4는 이미 구현된 대화 요약 표시로 실험하고, M8-T5의 E4 T4 구성은 1.1.0에서 뺀다. 1.1.0 전에는 실험 모드(I59)와 화면 사용 기록(I60)만 더하고 릴리스한다(I61).

**연구 설계 2와 2.0.0** (2026-11-12 사용자 결정, I62): 연구 설계를 [사용자 지시 오류와 에이전트의 대응](research/StudyDesign.md)으로 바꿨다. 1.1.0은 처음 설계(T1\~T6)의 고정판이다. 이후 작업은 M9(실험 자료)와 M10(지시 오류 중심 화면)을 먼저 하고, M10이 끝나면 2.0.0으로 릴리스한다. M3\~M8의 남은 태스크는 처음 설계의 것이라 보류한다(취소하지 않는다). 수업 실험(마감 2026-11-29)은 [미니 버전](research/StudyDesign.md#9-수업-실험-미니-버전)으로 하며, 2.0.0이 늦으면 1.1.0 화면으로 한다.

- 진행 순서: M9-T1 → M9-T2·M9-T3(팀의 과제 만들기와 함께) → M9-T4 → M9-T5. 화면은 M10-T1 다음에 M10-T2\~M10-T5를 하고 M10-T6로 마무리한다.
- 실험 자료가 가장 오래 걸리므로 M9를 먼저 시작하고, M10은 M9-T1이 끝나면 함께 진행한다.

**2.1.0: 실험 진행과 분석 도구** (2026-11-13 사용자 결정, I64): 2.0.0 다음에는 실험을 공정하게 진행하고 결과를 분석하는 도구를 M11로 한다. 기준선 조건도 같은 서버와 화면 사용 기록으로 재고(M11-T1), 공개 전에 실험 자료를 익명화하고(M11-T2), 신호 규칙의 정확도를 정답표로 재고(M11-T3), 화면 사용 기록을 시행별로 요약하고(M11-T4), 다른 코딩 에이전트와의 대응표를 만든다(M11-T5). 순서는 번호대로이며, 끝나면 2.1.0으로 릴리스한다. 수업 실험이 2.1.0 전에 시작되면 2.0.x로 하고, 시작 뒤에는 2.1.0을 내지 않고 실험이 끝난 뒤 낸다(PR 규칙의 기준판 규칙).
