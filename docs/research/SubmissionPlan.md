# 수업 이후 학회 제출 계획

이 문서는 수업 과제를 마친 뒤 IEEE VIS(TVCG 특별호) 등에 논문을 낼 때 지켜야 할 심사 지침과, 그에 맞춘 실험·제출 계획을 정리한다. 수업 과제의 논문 작성에는 영향을 주지 않는다. 학회 후보와 기준을 TVCG로 정한 근거는 [목표 학회 비교](TargetVenues.md)에, 지금 진행 중인 유저 스터디 결정은 [이슈](../Issue.md)의 I26에 있다. 관련 작업은 이슈 I56이다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

## 1. 조사 방법과 한계

- 2026-11-07에 IEEE VIS 공식 사이트의 2025·2026 안내를 직접 열어 확인했다(출처는 7절).
- 오늘 기준으로 VIS 2026 주기는 끝났고(학회 2026-11-09\~13) VIS 2027 안내는 아직 나오지 않았다. 아래는 2025·2026 안내 기준이며, 제출하는 해의 안내를 다시 확인해야 한다.
- TVCG에 직접 투고할 때의 심사자 양식은 공개 문서로 찾지 못했다. VIS 정규 논문은 TVCG 형식과 심사를 따르므로 VIS 안내를 기준으로 삼는다.

## 2. 지침에 적힌 것

| 항목 | 지침 내용 | 출처 |
| --- | --- | --- |
| 심사 기준 | 과학적 품질과 새로움, 예상 영향, 근거가 결과를 뒷받침하는 정도, 방법의 적절성, 연구 과정. 새롭고 의미 있는 기여를 선행 연구와 견주어 분명히 논해야 한다. | VIS 2025 공모, VIS 2026 제출 안내 |
| 특정 응용에 맞춘 연구 | "응용(Applications)" 영역의 기술적 해법은 "보통 특정 응용에 맞춘 것(typically application-specific)"이고 흔히 도메인 전문가와 함께 만든다. 응용 논문은 시각화 연구가 VIS 공동체 밖에서도 의미가 있음을 보여 준다. 다룰 주제로 실제 적용의 성공·실패 보고, 도메인 작업 흐름에 시각화를 통합하는 지침, 포괄적인 설계 연구를 든다. | VIS 2026 영역 모델 |
| 일반화 | 따로 요구하는 문구는 없다. 가장 가까운 것은 설계 연구 논문이 "다음 연구자가 기댈 수 있는 교훈이나 통찰"을 보여야 한다는 문구다. | VIS 2025 짧은 논문 공모 |
| 심사 태도 | "결함이 가장 적은 논문"이 아니라 대담하고 의미 있는 연구를 높이 산다. 그런 연구는 모든 기여를 완벽히 검증하지 못할 수 있다. 작은 수정으로 고칠 수 있는 것은 조건부 채택으로 다룬다. | VIS 2025 심사 안내 |
| 보충 자료 | 코드, 데이터, 실험 자극, 분석 코드를 권장한다. 필수는 아니고, 없다는 것만으로 떨어뜨릴 수 없지만 경계선 논문에서는 고려될 수 있다. 코드는 OSI 승인 라이선스(예: Apache 2.0), 그 밖의 자료는 변형을 허락하는 CC 라이선스(예: CC BY 4.0)를 권한다. 마감 뒤에는 밖에 둔 자료(GitHub, OSF 등)도 바꾸지 않는다. | VIS 2025 심사 안내, VIS 2026 제출 안내, 보충 자료 FAQ |
| IRB와 동의 | 사람을 대상으로 한 연구는 IRB(또는 윤리위원회)의 감독 아래 수행했다는 진술을 위원회 이름과 함께 논문에 넣고, 동의를 받았음을 밝혀야 한다. 받지 않았으면 이유를 설명한다. 근거는 IEEE 출판 운영 지침 8.1.1.E다. | VIS 2026 논문 위원장 안내 |
| 맹검 | 첫 심사는 이중 맹검이다. 공개된 소프트웨어는 익명화가 매우 어려울 수 있고, 도메인·협력 기관 같은 정보가 기여에 핵심이면 단일 맹검을 택할 수 있다. 조건부 채택 뒤 둘째 심사는 단일 맹검이다. | VIS 2026 제출 안내 |
| 분량과 일정 | 최종본은 본문 9쪽과 참고문헌 2쪽, 모두 11쪽까지다. 2026년에는 제목·초록 3월 21일, 본문과 보충 자료 3월 31일이 마감이었다. 심사자는 셋 이상이고 여러 차례 심사한다. | VIS 2026 제출 안내 |

## 3. 우리 연구에 주는 의미

- **Claude Code에 맞춘 도구라는 점은 문제가 되지 않는다.** 응용 영역은 특정 응용에 맞춘 해법을 전제로 한다. 응용 영역은 투고가 많은 영역이라(2025년 144편, 영역 위원회 요약의 검색 결과로만 확인) 경쟁은 치열하다.
- **영향과 새로움 점수를 위해 기여를 "코딩 에이전트 실행 기록"의 수준으로 쓴다.** 필수 요건은 아니지만 효과가 크다.
  - [과업과 데이터 추상화](../design/TaskAbstraction.md)의 과업(T1\~T6)과 정보 항목(D1\~D40)은 Claude Code에 묶여 있지 않다. 다른 코딩 에이전트(Codex CLI, Cursor 에이전트, OpenHands, SWE-agent)의 기록 필드와 정보 항목을 맞춘 대응표를 논문이나 부록에 넣는다.
  - 기여 목록: 실무 고충에서 나온 과업 분류, 데이터 추상화, 설계와 그 근거·검토한 대안([시각화 인코딩 설계](../design/VisualEncoding.md)), 평가, 도메인 작업 흐름(바이브 코딩)에 시각화를 통합하는 교훈.
- **데이터 형식 의존을 정직하게 다룬다.** 세션 기록은 공개 규격이 아니고 버전마다 바뀐다([데이터 소스의 주의 사항](../DataSource.md#32-주의-사항)). 연구에 쓴 Claude Code 버전을 밝히고, 타당성 위협에 적는다. hook이 공식 규격이라는 점은 장점으로 든다.
- **기준선을 과업 종류마다 정한다.** 현장 과업은 Claude Code 기본 화면, 통제 과업은 검색이 되는 텍스트 기록 보기다. 검색 같은 기본 기능도 없는 기준선은 허수아비 기준선이라는 지적을 받는다([시각화 원칙 조사의 흔한 함정](VisualizationPrinciples.md#74-흔한-함정)).
- **보충 자료로 재현성 우려를 줄인다.** 코드(이미 공개 저장소), 실험용 시나리오로 만든 익명 세션 기록 묶음, 과업지, 분석 코드를 낸다. 개인 기록을 실험에 쓰지 않기로 한 결정 덕분에 공개할 수 있다.

## 4. 실험 계획: 수업 실험과 제출용 실험

2026-11-07 사용자 결정: **수업 실험은 경험을 쌓는 파일럿으로 하고, 제출용 실험은 IRB 승인 뒤 다시 한다.**

| | 수업 실험 | 제출용 실험 |
| --- | --- | --- |
| 목적 | 과업·자료·절차를 실제 참가자로 다듬고, 수업 과제의 논문을 쓴다 | 학회 논문의 평가 |
| IRB | 출판에 쓰지 않는 수업 활동으로 진행한다. 윤리 절차(동의서, 참가자 번호, 보관·삭제, 속임 과업의 사후 설명)는 똑같이 지킨다 | 실험 전에 IRB 승인(또는 면제 판정)을 받는다 |
| 데이터 사용 | 학회 논문에 결과 수치·발언을 쓰지 않는다. "파일럿으로 과업과 절차를 고쳤다"는 언급이 괜찮은지는 IRB에 확인한다 | 논문에 쓴다 |
| 도구 버전 | 1.1.x(유저 스터디 기준판, [PR 규칙의 릴리스](../PullRequestRule.md#6-릴리스)) | 파일럿의 개선을 넣으면 1.2.x. 논문에 버전을 밝힌다 |
| 참가자 | 수업 동료 등 | 수업 실험 참가자와 정답 주석자는 빼는 것을 원칙으로 한다. 넣으면 경험 여부를 기록해 분석에서 따로 다룬다 |

**제출까지의 순서**

1. 수업 실험을 하면서 동의서, 사후 설명문, 데이터 관리 계획, 과업지, 진행자 대본을 IRB 신청에 쓸 수 있는 형태로 만든다.
2. 수업이 끝나면 IRB를 신청한다. 심사에는 보통 몇 주가 걸린다(소속 기관 일정을 확인한다).
3. 파일럿에서 배운 것을 반영해 도구(1.2.x)와 과업을 고친다. 형성 확인(과업 판정 절차와 화면을 도메인 사용자에게 확인받기)의 결과도 넣는다. 수업 실험에서 식별 과업으로 좁힌 T1·T2(I57)는 원래의 판정 과업(주장 ↔ 근거, 실패 → 변경의 성격)으로 되돌릴지 이때 정한다. 되돌리면 기준 사건 보기(M8-T2)가 필요하다.
4. 제출용 실험 계획을 OSF 등에 미리 등록한다(가설, 과업, 측정, 분석 방법, 표본 크기와 그 근거). 파일럿 결과에 맞춰 가설을 고쳤다는 의심을 막는다.
5. IRB 승인 뒤 제출용 실험을 한다. 표본은 12\~16명을 목표로 하되 파일럿의 효과 크기로 근거를 대 본다([시각화 원칙 조사의 참가자 수](VisualizationPrinciples.md#73-참가자-수)).
6. 논문을 쓰고 보충 자료를 준비한다. 마감(통상 3월 말) 전에 맹검 방식과 익명 자료를 정한다.

## 5. 제출 전 점검 목록

- [ ] IRB 승인(또는 면제 판정)을 실험 전에 받았고, 위원회 이름과 동의 절차를 논문에 적었다.
- [ ] 수업 실험의 데이터는 논문에 쓰지 않았다.
- [ ] 기여 목록이 Claude Code 밖에서도 의미를 가지는 항목을 둘 이상 담는다(과업 분류, 데이터 추상화, 교훈 등).
- [ ] 다른 코딩 에이전트 기록과 우리 정보 항목의 대응표가 있다.
- [ ] 연구에 쓴 Claude Code 버전과 AgentVis 버전을 밝혔다. 기록 형식 의존을 타당성 위협에 적었다.
- [ ] 기준선이 공정하다(통제 과업은 검색이 되는 텍스트 기록 보기).
- [ ] 선행 연구(특히 [AgentLens](RelatedWork.md#33-가장-가까운-경쟁자와의-차이))와의 차이를 분명히 썼다.
- [ ] 맹검 방식을 정했다. 이중 맹검이면 저장소 이름·계정·주소가 드러나지 않는 익명 사본과 익명 보충 자료를 준비했다. 단일 맹검이면 그 이유를 적었다.
- [ ] 보충 자료(코드, 익명 세션 기록 묶음, 과업지, 분석 코드)에 라이선스(코드 Apache 2.0 등, 자료 CC BY 4.0 등)를 붙였고, 마감 뒤에는 바꾸지 않는다.
- [ ] 분량(본문 9쪽 + 참고문헌 2쪽)과 TVCG 형식을 지켰다.
- [ ] 제출하는 해의 VIS 안내를 다시 확인했다.

## 6. 확인할 것

- 소속 기관 IRB의 규정: 수업 활동과 연구의 구분, 파일럿을 논문에 언급하는 범위, 심사 기간.
- 앞선 답에서 선례로 든 연구(TensorFlow 데이터 흐름 그래프 시각화의 VAST 2017 최우수 논문상, ActiVis)는 이번 조사로 확인하지 않았다. 논문에 인용하기 전에 확인한다.
