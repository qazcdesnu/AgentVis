# 목표 학회 비교

이 문서는 AgentVis 연구와 가까운 학회를 비교하고, 연구 절차와 논문의 기준으로 삼을 학회를 정한 근거를 남긴다. 연구 목적은 [제품 비전](../ProductVision.md#1-목적)에, 같은 분야 결과물이 어디에 실렸는지는 [관련 결과물 조사](RelatedWork.md#32-학술-시스템)에 있다. 관련 작업은 이슈 I30이다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

## 1. 연구의 성격

AgentVis 논문이 내세울 기여는 세 가지다([관련 결과물 조사의 기여 공간](RelatedWork.md#34-agentvis의-기여-공간)).

1. **데이터와 과업의 추상화**: Claude Code 작업 기록에서 무엇을 보여 줄지 고르고, 실무 고충을 시각화 과업(Q1\~Q6, 고충 6가지)으로 정의한다.
2. **시각화 설계**: 고충에 맞춰 추린 시각화와 그 설계 근거. 원본 기록만으로는 왜 부족한지도 함께 보인다.
3. **평가**: Claude Code 기본 UI와 비교한 유저 스터디.

이 구성은 시각화 분야의 **설계 연구(design study)** 형식과 같다. 설계 연구는 실제 사용자의 문제를 데이터·과업으로 추상화하고, 시각화를 설계하고, 사용자와 함께 검증한다. 형식의 근거는 Sedlmair, Meyer & Munzner(2012, "Design Study Methodology: Reflections from the Trenches and the Stacks", IEEE TVCG 18(12))와 Munzner의 중첩 모델([좋은 시각화 원칙 조사](VisualizationPrinciples.md#42-중첩-모델과-과업-추상화))이다. 대학원 수업의 과제 다섯 가지(데이터 선정, 시각화, 시각화가 필요한 이유, 유저 스터디, 논문)도 이 형식에 그대로 대응한다.

## 3. 결정

**1차 목표는 수업 과제를 먼저 완수하는 것이다.** 연구 절차와 논문은 **IEEE TVCG(IEEE VIS 정규 논문)의 기준**에 맞춰 설계 연구 형식으로 수행하고 쓴다. 실제 제출 여부, 학회, 시기는 과제를 완성한 뒤 정한다(2026-11-01 사용자 지시).

**TVCG 기준으로 정한 이유**
- **이유 1: 형식이 맞다.** 수업 과제 다섯 가지가 설계 연구 형식에 그대로 대응한다([1절](#1-연구의-성격)).
- **이유 2: 가장 가까운 선례가 TVCG에 실렸다.** 에이전트 행동 시각화 연구인 AgentLens가 TVCG에 실렸다.
- **이유 3: 주제가 VIS의 주제다.** 기여가 "무엇을 어떻게 보여 주는가"와 "그 효과의 검증"이다.
- **이유 4: 다른 학회에도 통한다.** TVCG 기준(추상화, 설계 근거, 평가)으로 만든 결과는 CHI 등에 맞게 고쳐 쓰기도 쉽다.

**제출 후보**(과제를 완성한 뒤 결정)

| 후보 | 고를 때 |
| --- | --- |
| IEEE VIS(TVCG) | 시각화 설계와 그 평가가 기여의 중심일 때. 마감은 통상 3월 말이다. |
| CHI | 유저 스터디의 발견("AI 에이전트와 바이브 코딩하는 사람이 무엇을 놓치고, 시각화가 그것을 어떻게 바꾸는가")이 시각화 설계보다 클 때. 마감은 통상 9월이다. |
| VL/HCC 또는 VISSOFT | 결과를 먼저 짧게 발표할 때 |

**논문 구성(설계 연구 형식)**

1. 문제와 동기
   - 실무 고충: [고충 조사](ClaudeCodePainPoints.md)
   - 원본 기록만으로 부족한 이유: [시각화 원칙 조사 2절](VisualizationPrinciples.md#2-시각화가-필요한-이유)
2. 관련 연구: [관련 결과물 조사](RelatedWork.md)
3. 데이터와 과업의 추상화: 작업 기록의 구조, 질문 Q1\~Q6, 고충 6가지를 과업으로
4. 설계: 화면 요소와 과업의 짝짓기, 설계 근거와 검토한 대안
5. 구현
6. 평가: 유저 스터디(이슈 I26), 사용 사례
7. 논의와 한계

## 4. 과제 수행에서 지킬 TVCG 기준

- **설계 근거를 남긴다.** VIS 심사는 "왜 이 인코딩인가", "어떤 대안을 검토했나"를 묻는다. 화면 재설계 문서에 과업 짝짓기 표, 검토한 대안, 버린 이유를 함께 적는다.
- **평가를 보강한다.** 유저 스터디에 사용 사례(실제 세션에서 찾아낸 문제)나 전문가 의견을 더하면 VIS의 평가 관행에 맞는다.
- **유저 스터디 설계(I26)의 측정 지표는 그대로 쓴다.** 정확도, 시간, NASA-TLX, SUS, 인터뷰는 VIS와 CHI 모두에서 통한다.
