# 커밋 규칙

이 문서는 git 커밋의 단위, 시점, 메시지 형식을 정한다. 모든 커밋은 [작업 관리 규칙](TaskRule.md)의 작업 ID에 묶인다. 메시지 형식(3절)은 [커밋 검사기](VerificationTools.md#7-커밋-검사기)가 검증하고, 커밋 단위와 시점(2절)은 작업자가 지킨다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## 1. 목적

커밋 이력만 보고도 각 변경이 어떤 작업(로드맵 태스크, 이슈, 핫픽스)에서 나왔는지 알 수 있게 한다. 커밋의 작업 ID로 [로드맵](Roadmap.md)·[이슈](Issue.md)의 할 일과 [완료](Done.md)의 상세 기록을 찾아갈 수 있다.

## 2. 커밋 단위와 시점

- 커밋 하나는 하나의 작업(또는 함께 처리한 몇 개의 작업)의 변경만 담는다. 서로 관계없는 작업의 변경을 한 커밋에 섞지 않는다.
- 작업을 끝내면 [완료 처리](TaskRule.md#43-완료)까지 마친 상태로 커밋한다. 그래서 완료 커밋에는 코드·문서 변경과 함께 로드맵·이슈의 `[x]`, 완료 기록이 들어간다.
- 작업이 길면 진행 중(`[~]`)에도 중간 커밋을 할 수 있다. 이때도 [검증 도구](VerificationTools.md)가 통과하는 상태에서만 커밋한다. 단, 작업을 시작하면서 코드 포인터를 먼저 건 단계처럼 포인터 검사기가 의도적으로 실패하는 상태는 예외이며, 그 사실을 커밋 본문에 적는다.
- 아직 시작하지 않은(`[ ]`) 작업의 ID로는 커밋하지 않는다.
- 커밋은 작업 브랜치에서 하고, 커밋하면 바로 원격에 push한다. `main`에는 직접 커밋하지 않으며, `main` 반영은 사용자가 PR을 병합해서 한다([PR 규칙](PullRequestRule.md)).

## 3. 메시지 형식

```text
<작업 ID>[, <작업 ID>…]: <요약>

<본문 (선택)>

<트레일러 (선택)>
```

**제목 줄**

- 작업 ID로 시작한다. 여러 작업이면 `, `로 구분해 모두 적는다. `I1-I5` 같은 범위 표기나 `M0` 같은 마일스톤만의 표기는 쓰지 않는다.
- ID 뒤에 `: `(콜론과 공백 하나)를 쓰고 요약을 적는다.
- 요약은 이 커밋이 한 일을 한국어 한 문장으로 적고, 마침표를 찍지 않는다.
- 제목 줄은 72자 이하로 쓴다.
- 작업 ID는 [로드맵](Roadmap.md)이나 [이슈](Issue.md)에 있어야 한다.

**본문**

- 제목 다음에 빈 줄 하나를 두고 쓴다.
- 무엇을 왜 바꿨는지 요약한다. 상세 내역은 완료 기록에 있으므로 반복하지 않는다.

**트레일러**

- `Co-Authored-By:` 같은 git 트레일러는 본문 뒤에 빈 줄을 두고 쓴다.

예:

```text
M1-T2: 이벤트 저장소의 원시 이벤트 저장·조회 구현

SQLite 스키마 1판과 EventStore를 추가했다. 중복 제거 키가 같은
세션 기록은 두 번째부터 저장하지 않는다.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## 4. 예외

- 병합 커밋은 검사하지 않는다.
- 이 규칙이 생기기 전의 첫 커밋 `2a80e26`(이 규칙의 기준 커밋)과 그 이전 커밋은 검사하지 않는다. 기존 이력은 고쳐 쓰지 않는다.

## 5. 강제

- git 저장소의 `.githooks/commit-msg` hook이 커밋할 때마다 [커밋 검사기](VerificationTools.md#7-커밋-검사기)로 메시지를 검사하고, 규칙에 맞지 않으면 커밋을 막는다.
- git 저장소를 새로 받으면 아래 명령으로 hook 경로를 설정한다. 이 설정은 git 저장소의 로컬 설정이다.

```sh
git config core.hooksPath .githooks
```

- hook을 우회하는 `git commit --no-verify`는 쓰지 않는다. 우회된 커밋이 있어도 이력 검사([6. 검증](#6-검증))에서 드러난다.

## 6. 검증

기준 커밋 이후의 모든 커밋 메시지를 검사한다. 작업을 끝낼 때 다른 검증 명령과 함께 실행한다.

```sh
uv run python -m tools.check_commits
```
