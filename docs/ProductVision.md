# 제품 비전

이 문서는 AgentVis가 무엇을 만들고 왜 만드는지 정한다. 모든 제품 기능 문서와 제품 코드는 이 문서를 근거로 한다. 분석에 쓰는 원천 데이터는 [데이터 소스](DataSource.md)에, 전체 문서 목록은 [문서 인덱스](index.md)에 있다.

## 1. 목적

AgentVis는 Claude Code 에이전트의 작업 과정을 시각화해, **에이전트가 어디서, 왜 사용자의 의도에서 벗어나는지** 진단하는 도구다.

Arize Phoenix 같은 LLM 관측 도구는 호출 단위의 트레이스(지연 시간, 토큰, 입출력)를 보여 주고, Langflow 같은 도구는 에이전트 흐름을 설계·실행하는 데 초점을 둔다. AgentVis의 관심사는 그와 다르다.

- 관측 단위는 개별 API 호출이 아니라 **사용자 지시 하나를 수행하는 과정 전체**다.
- 성능이 아니라 **실패, 반복, 우회(fallback), 지시 오해**를 찾아 드러내는 것이 목적이다.

## 2. 핵심 분석 질문

AgentVis는 아래 질문에 답할 수 있어야 한다. 기능은 이 질문 중 하나 이상에 답하기 위해서만 만든다.

| 번호 | 질문 |
| --- | --- |
| Q1 | 지시한 작업을 수행하기 위해 에이전트가 어떤 과정(단계와 도구 호출의 순서)을 거쳤는가? |
| Q2 | 어느 지점에서 실패했는가? |
| Q3 | 어떤 종류의 작업(도구, 명령, 파일 편집 등)에서 실패했는가? |
| Q4 | 어디서 같은 실패가 반복되었는가? |
| Q5 | 실패 후 어떤 fallback(다른 방법으로의 우회)이 일어났는가? |
| Q6 | 어느 지점부터 에이전트가 사용자의 지시를 잘못 이해했는가? |

## 3. 진단 신호

각 질문은 [데이터 소스](DataSource.md)에서 관찰 가능한 신호로 판정한다. "확정"은 기록에 명시된 사실이고, "추정"은 규칙이나 판정 모델로 해석한 결과다. 화면에는 둘을 항상 구분해 표시한다.

| 신호 | 판정 근거 | 구분 | 관련 질문 |
| --- | --- | --- | --- |
| 도구 실패 | 도구 결과의 오류 표시, 명령의 0이 아닌 종료 코드 | 확정 | Q2, Q3 |
| 권한 거부 | 사용자가 도구 실행을 거부한 기록 | 확정 | Q2, Q6 |
| 사용자 중단 | 사용자가 진행 중인 작업을 끊은 기록 | 확정 | Q2, Q6 |
| 반복 실패 | 같은 도구·유사한 입력의 실패가 연달아 발생 | 추정 | Q4 |
| fallback | 실패 직후 같은 목적을 다른 도구·명령·방법으로 다시 시도 | 추정 | Q5 |
| 작업 중 정정 | 에이전트가 작업하는 도중 사용자가 끼어들어 보낸 메시지 | 확정(발생) / 추정(의미) | Q6 |
| 다음 턴 정정 | 다음 사용자 지시가 직전 결과를 부정하거나 고치라고 요구 | 추정 | Q6 |

## 4. 범위

**포함**

- 사용자가 Claude Code 프로젝트 폴더를 선택하면 그 프로젝트의 세션들을 시각화한다.
- 진행 중인 Claude Code 세션의 작업 과정을 실시간으로 시각화한다.
- 진행 중인 세션과 지난 세션 모두 로컬에 저장된 Claude Code 세션 기록을 주된 내용으로 삼아 시각화한다.
- 사용자 지시(턴) 단위로 과정을 묶고, 그 안의 도구 호출 흐름과 [진단 신호](#3-진단-신호)를 표시한다.
- 여러 세션에 걸친 실패 유형 통계(어떤 도구·명령이 자주 실패하는지)를 보여 준다.

**포함하지 않음**

- 에이전트 흐름을 설계하거나 실행하는 기능.
- 토큰 비용, 지연 시간 같은 성능 모니터링(필요하면 보조 정보로만 표시한다).
- Claude Code 이외의 에이전트 지원.

## 5. 결정 사항

2026-10-31에 정한 제품의 기본 방향이다. 이 결정을 바꾸려면 이 절을 먼저 고친다.

| 항목 | 결정 | 내용 |
| --- | --- | --- |
| 데이터 수집 | 실시간, hook은 신호·세션 기록은 내용 | 기본은 Claude Code가 작업하는 동안 실시간으로 보여 주는 것이다. 작업 내용의 대부분(사고 과정, 작업 중 사용자 메시지, 권한 판정, 대화 구조)은 [세션 기록](DataSource.md#3-세션-기록-jsonl)에 있고 세션 기록도 실시간으로 쓰이므로, hook 이벤트를 받을 때마다 해당 세션 기록을 이어 읽는다. hook은 실시간 신호와 hook에만 있는 정보, 세션 기록 읽기가 실패할 때의 안전망을 맡는다. 지난 세션과 서버가 꺼져 있던 동안의 작업도 세션 기록으로 채운다. (2026-10-31 I17에서 "실시간 우선, 세션 기록으로 보완"을 바꿈) |
| 화면 형태 | 로컬 웹 앱 | uv로 실행하는 로컬 서버에 브라우저로 접속한다. |
| 추정 신호 판정 | 규칙 먼저, LLM은 나중 | 1단계는 규칙 기반으로 판정한다. 2단계에서 지시 오해처럼 의미 해석이 필요한 신호에 LLM 판정을 더한다. LLM 판정은 세션 내용을 외부 API로 보내므로 사용자가 켤 때만 동작한다. |
| 보기 단위 | 프로젝트 폴더 | 화면은 프로젝트 폴더 선택에서 시작하고, 선택한 프로젝트의 세션들을 보여 준다. 프로젝트 목록은 Claude Code를 썼던 프로젝트를 세션 기록에서 찾아 만들며, 목록에 없는 폴더는 경로를 직접 입력한다. 브라우저의 폴더 선택 창은 실제 절대 경로를 알려 주지 않으므로 쓰지 않는다. |
| 수집 범위 | 전역 수집, 화면에서 프로젝트별로 보기 | hook은 Claude Code 사용자 설정에 한 번만 설치해 모든 프로젝트의 이벤트를 모은다. 프로젝트를 선택하기 전에 진행된 작업도 놓치지 않기 위해서다. |
