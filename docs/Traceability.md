# 포인터 규약

이 문서는 문서와 코드를 양방향으로 연결하는 포인터의 형식과 규칙을 정한다. 코드 작업 전반의 규칙은 [코드 작업 규칙](CodeRule.md)에, 이 규약을 검증하는 도구는 [검증 도구](VerificationTools.md#4-포인터-검사기)에 있다. 전체 문서 목록은 [문서 인덱스](index.md)에서 확인한다.

## 1. 목적

- **문서 → 코드 포인터**는 문서가 규정하는 내용이 코드의 정확히 어느 부분에 구현되는지 가리키는 화살표다.
- **코드 → 문서 포인터**는 코드가 어떤 문서를 근거로 작성되었는지 가리키는 화살표다.

줄 번호는 코드가 조금만 바뀌어도 어긋난다. 그래서 문서 → 코드 포인터는 줄 번호 대신 AST(추상 구문 트리)의 심볼 이름으로 대상을 가리킨다. 검사기는 대상 파일을 AST로 파싱해 그 심볼이 실제로 존재하는지 확인한다.

## 2. 문서에서 코드로 가는 포인터

마크다운 링크 문법을 그대로 쓴다. 링크 대상이 코드 파일(`.py`)이면 코드 포인터로 취급한다.

```markdown
[표시 이름](<코드 파일 상대 경로>#<한정 이름>)
```

- **경로**: 링크를 거는 문서 위치를 기준으로 한 상대 경로다. 일반 문서 링크와 같다.
- **한정 이름(qualified name)**: 모듈 안에서 심볼에 이르는 이름을 `.`으로 이은 것이다.
  - 최상위 함수·클래스: `main`, `ModuleIndex`
  - 메서드·중첩 클래스: `ModuleIndex.lookup`
  - 모듈 또는 클래스 수준의 상수·변수(대입문): `REPO_ROOT`, `Link.source`
- **`#` 이후를 생략하면** 파일(모듈) 전체를 가리킨다.
- **줄 번호(`#L10` 등)는 금지**한다.

예시 (`docs/` 아래 문서에서):

```markdown
링크 검사는 [check_links](../tools/check_docs.py#check_links)가 수행한다.
```

코드 블록과 인라인 코드 안의 링크는 예시로 보고 검사하지 않는다.

## 3. 코드에서 문서로 가는 포인터

`@doc:` 태그 뒤에 근거 문서의 경로를 적는다.

```text
@doc: <문서 경로>[#<제목 앵커>]
```

- **경로**: 저장소 루트 기준 경로다. 코드 파일의 위치와 무관하게 항상 같은 문자열로 같은 문서를 가리키도록 하기 위해서다. 예: `docs/VerificationTools.md`
- **제목 앵커**: 선택 사항이다. 문서의 제목에서 만든 앵커로, 만드는 방식은 [문서 작업 규칙](DocumentationRule.md#3-링크-규칙)의 앵커 규칙과 같다.
- 한 심볼에 여러 개를 달 수 있다. 태그 하나당 한 줄을 쓴다.

포인터를 다는 위치는 두 가지다.

**docstring (기본)**: 모듈, 클래스, 함수의 docstring 안에 쓴다. 포인터는 그 docstring의 주인 심볼에 속한다.

```python
def check_links(root: Path) -> list[Problem]:
    """문서 링크의 대상 파일과 앵커가 존재하는지 검사한다.

    @doc: docs/VerificationTools.md#3-문서-링크-검사기
    """
```

**주석**: docstring을 둘 수 없는 상수·변수에 쓴다. 주석은 독립된 줄에 있어야 하며, 포인터는 그 아래에서 처음 나오는 코드 줄에서 시작하는 심볼(데코레이터 포함)에 속한다. 그 사이에는 빈 줄이나 다른 주석 줄만 올 수 있다.

```python
# @doc: docs/VerificationTools.md#2-공통-모듈
CODE_ROOTS = ("src", "tools", "tests")
```

심볼에 속하지 않는 `@doc:` 주석(아래에 심볼 정의가 없거나, 코드 줄 끝에 붙은 주석)은 오류다.

## 4. 커버리지 규칙

코드 루트(`src/`, `tools/`, `tests/`) 아래의 모든 `.py` 파일에 다음을 요구한다.

- 모듈 docstring에 `@doc:` 포인터가 하나 이상 있어야 한다.
- 이름이 `_`로 시작하지 않는 최상위 클래스·함수는 자기 자신에게 `@doc:` 포인터가 하나 이상 있어야 한다.

내용이 비어 있는 파일(예: 빈 `__init__.py`)은 제외한다. 메서드, 비공개 심볼, 상수는 필수는 아니지만 필요하면 포인터를 달 수 있다.

## 5. 상호 참조 규칙

두 심볼이 같은 파일 안에 있고, 같은 심볼이거나 한쪽이 다른 쪽을 포함(조상·자손)하면 두 심볼은 **관련 있다**고 한다. 모듈 자체는 그 파일의 모든 심볼의 조상이다.

- 문서 D가 심볼 S를 가리키면, S와 관련 있는 심볼 중 하나가 D를 가리켜야 한다.
- 심볼 S가 문서 D를 가리키면, D는 S와 관련 있는 심볼 중 하나를 가리켜야 한다.

상호 참조를 판단할 때 앵커는 비교하지 않고 문서 파일만 비교한다. 이 규칙 때문에 한 방향 포인터만 있는 상태는 검증을 통과하지 못한다.

## 6. 검증

이 규약은 [포인터 검사기](VerificationTools.md#4-포인터-검사기)가 검증한다. 검사 항목은 다음과 같다.

1. 문서 → 코드 포인터: 대상 파일 존재, 줄 번호 금지, AST 상 심볼 존재.
2. 코드 → 문서 포인터: 대상 문서 존재, 앵커 존재, 주석 포인터의 소속 심볼 존재.
3. [커버리지 규칙](#4-커버리지-규칙).
4. [상호 참조 규칙](#5-상호-참조-규칙).
