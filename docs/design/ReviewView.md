# 지시 대조 보기 설계 (2.0.0)

이 문서는 [연구 설계 2](../research/StudyDesign.md)의 화면 요구 R1\~R5를 2.0.0 화면으로 옮긴다. 무엇을 어떤 시각 요소로 그리는지, 왜 그렇게 했고 어떤 대안을 버렸는지, 분석기가 무엇을 계산하는지를 정한다. 입력은 [과업과 데이터 추상화 2](TaskAbstraction2.md)의 정보 항목 N1\~N9이고, 그리지 않는 부분은 1.1.0 화면([웹 UI 설계](WebUI.md), [작업 흐름 그래프](FlowGraph.md))을 그대로 쓴다. 관련 작업은 M10-T1\~M10-T6이다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

## 1. 설계 원칙

1. **지시가 축이다(R1).** U2·U3의 필수 정보가 모두 지시 문장에 연결된다([설계 함의 1](TaskAbstraction2.md#42-설계-함의)). 지시를 늘 보이는 자리에 두고, 다른 요소는 지시의 문장을 가리킨다.
2. **드문 사건을 앞으로(R2·R3).** 에이전트의 해석과 어긋난 증거는 기록 속 드문 사건이다. 따로 모은 목록으로 앞에 내고, 흐름 위에도 표지로 남긴다.
3. **정상 작업은 뒤로(R4).** 문제없이 지나간 구간은 접거나 흐리게 한다. 지우지 않는다. 시간의 연속성과 원본 확인을 지키기 위해서다.
4. **판정하지 않는다(R5).** 모든 신호는 규칙으로 찾은 추정이다. 화면은 "추정" 표지와 근거(원문 문장, 출력 줄)를 함께 보이고, "지시가 틀렸다" 같은 결론은 쓰지 않는다.
5. **1.1.0의 화면을 깨지 않는다.** 새 상자 하나를 더하고, 그래프와 목록에는 표지와 흐림만 더한다. 처음 설계(T1\~T6)의 기능은 그대로 남아 이전 설계로 돌아가 비교할 수 있다.

## 2. 배치

세션 상세의 상자([웹 UI 설계 2절](WebUI.md#2-화면-구성))에 **지시 대조** 상자를 턴 선택과 작업 흐름 사이에 넣는다. 턴 범위의 상자라, 고른 턴의 지시를 대상으로 한다. 실험 기록은 턴이 하나라 곧 과제 지시다.

```text
┌ 세션 정보 ───────────────────────────────────────────────────────────┐
┌ 세션 전체 흐름 (턴이 하나면 접힘) ───────────────────────────────────┐
┌ 턴 선택 ─────────────────────────────────────────────────────────────┐
┌ 지시 대조 ───────────────────────────────────────────────────────────┐
│ 지시                                                                  │
│  ①`total([100.0], "save10")`가 90.0이 아니라 100.0을 돌려줍니다.      │
│  ②`invoice.py`의 `total`에서 `round` 처리가 … 고쳐 주세요.  [신호 3] │
│  ③테스트는 `python3 -m unittest …`로 돌립니다.                        │
│ ─────────────────────────────────────────────────────────────────── │
│ 신호 (추정) · 문장 ② 만 보기 ✕                                        │
│  00:49:45  ↗ 지시 밖 작업   discount.py 읽음                    ②   │
│  00:49:45  ◇ 재현           테스트 실패: test_code_is_case_…   ①   │
│  00:49:47  ❝ 해석           "`round` isn't the cause. …"        ②   │
│  00:49:48  ↗ 지시 밖 작업   discount.py 고침                    ②   │
└──────────────────────────────────────────────────────────────────────┘
┌ 턴 #1 작업 흐름   [흐름 그래프 | 목록] ──────────────────────────────┐
│  (신호가 있는 노드에 표지, 정상 구간은 흐리게 · 목록에서는 접힘)      │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. 요소와 인코딩

### 3.1 지시 패널 (R1, N1·N2, M10-T2)

| 항목 | 내용 |
| --- | --- |
| 정보 | N1 지시 문장, N2 지시가 가리킨 대상, 문장마다 연결된 신호 수 |
| 인코딩 | 지시 원문을 문단 그대로 보이고, 문장마다 앞에 원 숫자(①②…)를 단다. N2의 대상은 고정폭 글꼴과 밑줄로 표시한다. 신호가 연결된 문장 끝에 `신호 n` 칩을 단다. |
| 상호작용 | 문장(또는 칩)을 누르면 아래 신호 목록을 그 문장의 신호만 보이게 거른다(다시 누르면 해제). 거른 상태는 해시(`sentence=`)에 둔다. |
| 이유 | 지시를 문장 목록으로 쪼개 표로 보이면 읽는 흐름이 깨진다. 원문 그대로 두고 번호만 달아 다른 요소가 "어느 문장"을 가리킬 수 있게 했다. 대상은 판정 규칙의 근거라 원문 안에서 바로 보여야 한다. |
| 버린 대안 | (가) 지시와 행동을 좌우로 놓고 선으로 잇는 정렬 보기: 문장 하나에 사건 여럿이 이어져 선이 엉키고 가로 폭을 크게 쓴다. (나) 지시를 접힌 칸에 두기(1.1.0 방식): U2의 축인데 찾아 펼쳐야 한다. |

### 3.2 신호 목록 (R2·R3, N3\~N8, M10-T3·M10-T4)

| 항목 | 내용 |
| --- | --- |
| 정보 | N3 해석 문장, N4 사용자에게 한 질문, N5 지시 밖 작업, N6 재현 시도와 결과, N7 지목 위치 수정 뒤 남은 실패, N8 충돌하는 테스트 결과 |
| 인코딩 | 시간 순서의 줄 목록. 줄마다 시각, 종류 기호와 이름, 한 줄 요약(근거 원문의 앞부분), 연결된 지시 문장 번호. 종류는 기호와 글자로 구분하고 색은 쓰지 않는다(종류가 여섯이라 색만으로는 구분이 어렵고, 색은 1.1.0에서 도구 상태에 이미 쓴다). 머리에 "추정" 표지를 둔다. |
| 기호 | `❝ 해석`(N3), `? 질문`(N4), `↗ 지시 밖`(N5), `◇ 재현`(N6), `✕ 남은 실패`(N7), `⇄ 충돌`(N8) |
| 상호작용 | 줄을 누르면 그 단계를 고른다(해시 `step=`). 흐름 그래프에서는 그 노드가 열리고, 목록 보기에서는 그 단계로 스크롤한다. 1.1.0의 단계 선택과 같은 경로라 노드 상세에서 원문을 바로 본다. |
| 비어 있을 때 | "규칙으로 찾은 신호가 없습니다"라고 쓴다. 신호가 없다는 것이 지시에 잘못이 없다는 뜻은 아님을 마우스 설명에 적는다(R5). |
| 이유 | U1의 답(처음 알아챈 단계와 대응)은 드문 사건 몇 개에 있다. 그래프에서 표지로만 보이면 넓은 그래프를 훑어야 찾는다. 목록은 개수와 순서를 바로 보인다. |
| 버린 대안 | (가) 그래프 표지만 두기: 넓은 그래프에서 드문 표지를 놓친다. (나) 종류별로 묶은 표: 시간 순서(무엇이 먼저였나)가 U1의 답이라 묶으면 잃는다. |

### 3.3 흐름 위의 표지와 흐림 (R2·R3·R4, M10-T3\~M10-T5)

- **그래프 노드 표지**: 신호가 있는 노드의 표지 글자(1.1.0의 [노드 표지](FlowGraph.md#32-노드) `marks`)에 신호 기호를 더한다. 예: `❝ ↗`. 범례에 기호를 더한다.
- **정상 구간 흐림**(N9): 정상 구간에 든 노드는 불투명도 0.35로 흐리게 그린다. 고른 노드와 신호 노드는 흐리지 않는다. 그래프에서 노드를 지우지 않는 이유는 시간축과 병렬 구조가 깨지기 때문이다.
- **목록 보기 접기**(N9): 정상 구간의 연속한 단계 3개 이상을 한 줄 `정상 작업 n단계 · 걸린 시간 ▸`로 접는다. 누르면 펼친다. 고른 단계가 접힌 구간 안에 있으면 그 구간은 펼친다.
- **세션 전체 흐름 상자**: 턴이 하나인 세션에서는 처음에 접어 둔다. 턴 시퀀스가 한 칸뿐이라 정보가 없고, 회의에서 지적한 "정보가 너무 많다"를 줄인다. 상자 제목을 누르면 편다.

### 3.4 1.1.0에서 남기고 뺀 것

| 요소 | 2.0.0 | 이유 |
| --- | --- | --- |
| 세션 정보, 턴 선택 | 그대로 | 맥락 |
| 세션 전체 흐름(턴 시퀀스, 배지, 완료 보고·테스트 변경 목록) | 남김. 턴이 하나면 접음 | 여러 턴 세션에서는 여전히 쓸모가 있다 |
| 흐름 그래프, 목록, 노드 상세 | 그대로, 표지와 흐림·접기만 더함 | 원본 확인의 경로 |
| 테스트 사건 표지(M8-T6) | 그대로 | N6\~N8이 그 위에 선다 |

## 4. 분석기: 지시 대조 모델

`review_turn(view, turn_index) -> Review | None`(M10-T2에서 만든다)이 고른 턴의 지시 대조 모델을 만든다. 입력은 1.1.0 분석기의 세션 모델([분석기 설계](Analysis.md))이다. 규칙은 모두 추정이며, 아래는 [정보 항목](TaskAbstraction2.md#3-새-정보-항목)의 판정 방법을 구현 수준으로 정한 것이다.

### 4.1 모델

| 필드 | 뜻 |
| --- | --- |
| `turn` | 턴 순번 |
| `sentences` | N1. `{index, text, start, end, targets}` 목록. `start`·`end`는 지시 원문에서의 글자 위치, `targets`는 N2 `{text, kind, start, end}`(`kind`: `path`, `symbol`, `test`, `command`) |
| `signals` | N3\~N8. `{kind, step_id, at, summary, sentence, detail}` 목록, 시간 순서. `kind`는 `interpret`, `ask`, `outside`, `repro`, `remaining_failure`, `conflict`. `sentence`는 연결된 문장 번호 또는 null. `detail`은 종류마다 근거(원문 문장, 파일 경로, 테스트 이름 등) |
| `quiet_steps` | N9. 정상 구간에 든 단계 ID 목록 |

API는 `GET /api/sessions/{id}/turns/{index}/review`다. 턴이 없으면 `404`다.

### 4.2 규칙 (M10-T2\~M10-T5에서 구현하며 채운다)

- **N1 문장 나누기**: 코드 블록(```` ``` ````)은 한 문장으로 둔다. 그 밖에서는 줄바꿈과 문장 끝(`.`, `?`, `!` 뒤 공백, 또는 한국어 종결 `다.`·`요.`)에서 나눈다. 백틱 안의 마침표에서는 나누지 않는다.
- **N2 대상**: 백틱 안의 글을 대상으로 한다. 경로 모양(`/`가 있거나 확장자로 끝남)이면 `path`, `test_`로 시작하거나 `Test`로 시작하는 이름이면 `test`, 공백이 있고 첫 낱말이 명령 모양이면 `command`, 그 밖은 `symbol`이다. `symbol`의 함수 호출 모양 `f(...)`은 이름 `f`만 쓴다.
