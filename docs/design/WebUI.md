# 웹 UI 설계

이 문서는 AgentVis의 웹 화면(`src/agentvis/web/`)을 설계한다. 화면이 보여 주는 데이터는 [분석기 설계](Analysis.md)의 조회 API가 주고, 화면이 답해야 할 질문은 [제품 비전의 핵심 분석 질문](../ProductVision.md#2-핵심-분석-질문)에 있다. 관련 태스크는 [로드맵](../Roadmap.md#m4-실시간-웹-ui)의 M4-T2~M4-T5다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

2026-10-31 사용자 방침: "보면서 나중에 추가하고 고치면 된다." 이 문서는 첫 화면을 만들기 위한 권장안이며, 화면을 보고 고친다.

## 1. 기술과 라이브러리

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 화면 기술 | 빌드 단계 없는 HTML·CSS·JavaScript(ES 모듈) | [시스템 구조의 기술 선택](../Architecture.md#6-기술-선택)대로 도구 체인을 늘리지 않는다. |
| 시각화 라이브러리 | 첫 화면(목록)은 쓰지 않는다. [작업 흐름 그래프](FlowGraph.md)는 **D3**를 쓴다. | 목록은 CSS 세로 타임라인으로 충분하다. 그래프는 시간축 척도, 확대·이동, 곡선 간선이 필요하고, D3는 이를 세밀하게 제어할 수 있는 표준 도구다. 라이브러리는 [1.1절](#11-저장소에-넣은-라이브러리)대로 저장소에 넣어 쓴다. |
| 제공 방식 | 서버 앱이 `web/` 폴더를 정적 파일로 제공한다. `GET /`는 `index.html`이다. 응답마다 다시 확인하라는 캐시 지시를 붙인다([수집기 설계](Collector.md#2-http-엔드포인트), H5). | 별도 웹 서버 없이 `agentvis serve` 하나로 쓴다. 고친 화면 파일이 새로고침만으로 반영되어야 팀원이 예전 화면을 보지 않는다. |
| 갱신 | 첫 화면은 "새로고침" 버튼으로 다시 불러온다. 실시간 갱신은 M4-T2(SSE)에서 붙인다. | |

### 1.1 저장소에 넣은 라이브러리

화면이 쓰는 외부 라이브러리는 **외부 CDN에서 받지 않고, 파일을 저장소의 `src/agentvis/web/vendor/`에 넣어 우리 서버가 제공한다.** CDN(Content Delivery Network)은 남이 운영하는 파일 배포 서버로, 화면을 열 때마다 브라우저가 그곳에서 라이브러리를 받아 온다. 2026-10-31에 사용자와 이 결정을 다시 검토했고(I24), 아래 이유로 유지한다.

| 기준 | 외부 CDN | 저장소에 넣기 |
| --- | --- | --- |
| 보안 | 화면에는 로컬 작업 기록 전체(명령, 파일 내용, 경로)가 올라온다. CDN의 파일이 바뀌거나 오염되면 그 스크립트가 이 내용을 읽어 밖으로 보낼 수 있다. 무결성 해시(SRI)로 줄일 수는 있다. | 저장소에 커밋해 검토한 파일만 실행된다. |
| 오프라인 | 인터넷이 없으면 화면이 깨진다. | 항상 동작한다. |
| 재현성 | 같은 주소의 내용이 바뀔 수 있다. | 커밋한 버전 그대로다. |
| 비용 | 없음 | 파일 하나(수백 KB)를 저장소에 두고, 판올림을 직접 한다. |

**넣는 절차**
1. 공식 배포처(npm 레지스트리의 패키지 압축 파일)에서 정확한 버전을 받는다. 받은 압축 파일을 레지스트리가 공개한 무결성 값(`dist.integrity`, SHA-512)과 대조한다.
2. 화면이 쓰는 배포 파일(예: `dist/d3.min.js`)과 라이선스 파일만 `vendor/`에 `<이름>-<버전>.<확장자>`, `LICENSE-<이름>.txt`로 둔다. 파일 내용은 고치지 않는다. git이 줄바꿈을 바꾸지 않도록 `.gitattributes`에서 `vendor/`를 `-text`로 둔다([운영체제 이식성](../CodeRule.md#31-운영체제-이식성)).
3. 아래 표에 파일, 버전, 라이선스, 출처, SHA-256을 적는다. 판올림할 때도 같은 절차를 밟고 표를 고친다.
4. `index.html`에서 `app.js`보다 먼저 일반 `<script>`로 불러온다. D3의 배포 파일은 전역 변수 `d3`를 만든다.

**넣은 라이브러리**

| 파일 | 라이브러리 | 버전 | 라이선스 | 출처 | SHA-256 |
| --- | --- | --- | --- | --- | --- |
| [d3-7.9.0.min.js](../../src/agentvis/web/vendor/d3-7.9.0.min.js) | D3 | 7.9.0 | ISC ([LICENSE-d3.txt](../../src/agentvis/web/vendor/LICENSE-d3.txt)) | npm `d3@7.9.0` `dist/d3.min.js` | `f2094bbf6141b359722c4fe454eb6c4b0f0e42cc10cc7af921fc158fceb86539` |

2026-10-31 M4-T8: `https://registry.npmjs.org/d3/-/d3-7.9.0.tgz`의 SHA-512가 레지스트리의 `dist.integrity`와 같음을 확인했다.

[웹 정적 파일 검사기](../VerificationTools.md#10-웹-정적-파일-검사기)가 이 절의 규칙 중 기계적으로 확인할 수 있는 부분을 검사한다.
- `vendor/`의 모든 파일이 이 표에 있고, 그 SHA-256이 표와 같은가
- 우리가 쓴 화면 파일에 외부 주소가 없는가

## 2. 화면 구성

세 영역을 가로로 놓는다. 화면이 좁으면 위아래로 쌓는다.

```text
┌──────────────┬──────────────────────┬───────────────────────────────────────────────┐
│ 프로젝트     │ 세션                 │ 세션 상세                         [새로고침]  │
│              │                      │ 일단 먼저 우리는 문서 규칙부터…  턴 51 · 실패 15 │
│ ▸ AgentVis   │ ▸ 일단 먼저 우리는…  │ ───────────────────────────────────────────── │
│   ~/Desktop/ │   10-31 04:41        │ ▾ #2 코드 작업 규칙 문서도 만들어라…  ✕2  ended │
│   세션 1     │   턴 51 · 실패 15    │   ◦ 생각 (접힘)                                │
│ ▸ ProjInit   │                      │   ▪ Write docs/CodeRule.md            ✓       │
│ ▸ AI윤리     │                      │   ▪ Bash python3 -m tools.check_docs  ✕ 오류   │
│   …          │                      │   ★ 사용자: 파이썬은 무조건 uv 환경에서 써라. │
│              │                      │   ▪ Bash uv init …                    ✓       │
│              │                      │ ▸ #3 …                                         │
└──────────────┴──────────────────────┴───────────────────────────────────────────────┘
```

- **프로젝트**(`GET /api/projects`): 이름, 상위 경로, 세션 수, 마지막 활동. 폴더가 없는 프로젝트는 흐리게 표시한다. 목록에 없는 폴더의 경로 직접 입력은 M4-T5에서 더한다.
- **세션**(`GET /api/sessions?project=…`): 제목, 마지막 활동, 턴 수, 도구 호출 수, 실패 수(0보다 크면 강조).
- **세션 상세**(`GET /api/sessions/{id}`): 아래 네 상자. 턴은 한 번에 하나를 고르며, 처음에는 마지막 턴을 고른다.
- **세션 상세의 상자**(I36): 세션 상세는 서로 다른 정보를 보여 주는 네 부분으로 이루어지며, 각 부분을 테두리와 배경이 있는 상자로 묶고 상자 왼쪽 위에 작은 제목을 단다. 위에서 아래로 놓는다.

  | 순서 | 상자 제목 | 내용 | 범위 |
  | --- | --- | --- | --- |
  | 1 | 세션 정보 | 제목, 프로젝트, 턴 수, 도구 호출 수, 실패 수 | 세션 |
  | 2 | 세션 전체 흐름 | [개요 띠와 이동 배지](#7-세션-개요-띠와-이동-배지) | 세션 |
  | 3 | 턴 선택 | 턴 고르기 상자(순번, 지시 첫 줄, 실패 수), 고른 턴의 정보(시작 시각, 상태, 도구 호출 수, 실패 수), 여러 줄 지시의 전문(접힘) | 턴 |
  | 4 | `턴 #n 작업 흐름` | 제목 줄 오른쪽의 `흐름 그래프 \| 목록` 단추, 고른 턴의 [작업 흐름 그래프](FlowGraph.md#6-화면)와 노드 상세, 또는 고른 턴의 단계 목록([3절](#3-턴과-단계-표시)) | 턴 |

  세션 범위 상자(1, 2)와 턴 범위 상자(3, 4)는 간격을 더 벌려 두 묶음으로 보이게 한다.

  **책임 나누기**: 상자마다 맡는 일이 하나다. 3번 상자는 **어떤 턴을 볼지**만 정하고, 두 보기에서 똑같다. `흐름 그래프 | 목록` 단추는 **고른 턴의 작업 흐름을 어떤 방식으로 그릴지**만 정하므로 그 흐름을 그리는 4번 상자의 제목 줄에 둔다. 단추를 바꿔도 고른 턴과 고른 단계는 그대로다(I36, 2026-11-07 사용자 지시).
- **사이드바 접기**(I35): 프로젝트·세션 영역의 제목 줄에 접기 단추(`◂`)를 둔다. 누르면 그 영역이 32px 너비의 세로 띠로 접히고, 띠에는 펴기 단추(`▸`)와 세로 글자 제목만 남는다. 두 영역은 따로 접는다. 세션 상세가 남은 폭을 모두 쓴다. 단추의 `aria-expanded`가 접힘 상태를 나타낸다. 접힘 상태는 보는 사람의 화면 취향이라 해시가 아닌 브라우저 저장소(`localStorage`)에 두고, 저장소를 쓸 수 없으면 펼친 상태로 시작한다. 좁은 화면(위아래로 쌓는 배치)에서는 접으면 목록만 숨기고 제목 줄은 남긴다.
- 선택 상태(프로젝트, 세션)는 URL의 해시(`#project=…&session=…`)에 둔다. 새로고침하거나 주소를 공유해도 같은 화면이 열린다.
- 세션 상세에는 이 문서의 목록 보기와 함께 턴별 [작업 흐름 그래프](FlowGraph.md#6-화면) 보기를 둔다(M4-T8).

## 3. 턴과 단계 표시

**턴 정보**: 순번, 사람이 입력한 지시(첫 줄, 여러 줄이면 펼쳐서 전체), 상태(`running`·`ended`·`failed`), 도구 호출 수, 실패 수, 시작 시각. 턴 선택 상자에 둔다([2절](#2-화면-구성)).

**단계**: [분석기 설계의 단계 종류](Analysis.md#4-단계)마다 표시를 정한다. 단계는 시간순 세로 타임라인이며, 색과 기호로 종류와 상태를 구분한다.

| 단계 | 표시 |
| --- | --- |
| `thinking` | 흐린 글씨, 기본은 접힘(첫 줄만). 펼치면 전문. 걸린 시간과 토큰이 있으면 `생각 4.2초 · 254토큰`처럼 앞에 적는다. 내용이 비었으면 펼칠 수 없는 한 줄로 `(내용이 기록에 남지 않음)`을 붙인다(I33). |
| `text` | 모델 응답. 기본 글씨. 길면 일부만 보이고 펼친다. |
| `tool_call` | 도구 이름 + 입력 요약(Bash는 `command`, 파일 도구는 `file_path`, 그 밖은 입력 JSON 앞부분) + 상태 기호. 펼치면 입력 전체, 결과, 오류, 실행 시간, 권한 요청 여부. 서브에이전트가 있으면 그 단계들을 들여써서 펼친다. |
| `user_message` | 이름은 **작업 중 사용자 메시지**다. **강하게 강조**(눈에 띄는 배경). 작업 도중 사람이 보낸 메시지로, 지시 오해(Q6)를 볼 때 가장 중요한 지점이다. |

**사람이 보낸 두 메시지**(I39): 둘 다 사람이 보냈지만 기록과 역할이 다르므로 나눠 부른다([과업과 데이터 추상화의 D1·D2](TaskAbstraction.md#31-지시와-대화)).

| 이름 | 원천 | 역할 | 표시 |
| --- | --- | --- | --- |
| 턴 시작 지시 | 턴을 시작하는 사람 입력 `user` 기록(`promptId`). 턴마다 하나, 맨 앞 | 무엇을 하라고 했는가 | 노란 원 |
| 작업 중 사용자 메시지 | 진행 중인 턴에 전달된 `queued_command` 첨부. 턴 안에 0개 이상 | 끼어들어 정정·추가 지시를 한 지점 | 노란 마름모(◆), 흐름 그래프에서는 모든 줄을 가로지르는 세로 점선 |

사람이 보낸 것은 같은 노란색 계열(`--user-message-line`)로 묶고 모양으로 둘을 가른다. 시스템이 보낸 알림은 회색으로 둔다. 화면의 모든 곳(목록, 노드 상세, 턴 선택, 개요 띠, 그래프, 범례)에서 이 이름과 모양을 쓴다.
| `notification` | 흐린 한 줄(출처: 작업 알림, 하위 에이전트 보고, 사용자 셸 명령). 펼치면 전문. |
| `hook_failure` | 경고 색 한 줄. "이 구간의 hook 수집이 빠짐". |
| `compact` | 가로 구분선 "대화 요약(문맥 압축)". 대화가 길어져 Claude Code가 앞 대화를 요약문으로 바꾼 지점이다. 이 뒤로 에이전트는 앞의 세부 내용을 요약으로만 기억한다(I39). |
| `subagent` | 연결되지 않은 서브에이전트. 들여쓴 단계 묶음. |

**도구 호출 상태 기호와 색**

| 상태 | 기호 | 색 |
| --- | --- | --- |
| `success` | ✓ | 초록 |
| `error` | ✕ | 빨강 |
| `interrupted` | ⏸ | 주황 |
| `running` | ● | 파랑 |
| `unfinished` | ? | 회색(권한 거부·중단의 후보) |

## 4. 보안

- 세션 기록의 모든 텍스트는 신뢰할 수 없는 데이터다(다른 웹 페이지 내용, 명령 출력 등이 들어 있다). 화면에 넣을 때는 항상 `textContent`로 넣고 `innerHTML`을 쓰지 않는다. 저장된 텍스트가 스크립트로 실행되는 것(XSS)을 막기 위해서다.
- 화면은 같은 서버의 조회 API와 정적 파일만 `GET`으로 부른다. 외부 주소로 요청하지 않는다(외부 CDN, 글꼴 포함). 라이브러리는 [1.1절](#11-저장소에-넣은-라이브러리)대로 저장소에 넣어 쓴다.
- 모든 요청은 서버의 [요청 검증](Collector.md#21-요청-검증) `Host` 검사를 받는다. 화면은 `http://127.0.0.1:<포트>/` 또는 `http://localhost:<포트>/`로 연다.

| `src/agentvis/web/vendor/` | 저장소에 넣은 외부 라이브러리([1.1절](#11-저장소에-넣은-라이브러리)) |

[서버 앱](../../src/agentvis/server.py#create_app)은 조회 API 경로를 먼저 등록하고 마지막에 `web/`를 `/`에 정적 파일로 연결한다. 정적 파일 연결은 [수집기 설계의 서버 앱](Collector.md#2-http-엔드포인트)에 더한다. 화면 코드는 Python이 아니므로 포인터 커버리지 검사 대상이 아니며, 이 문서가 파일 단위로 가리킨다.

## 6. 테스트

- [tests/test_api.py](../../tests/test_api.py)에서 `TestClient`로 `GET /`가 `index.html`을, `/app.js`·`/style.css`·`/graph.js`·`/overview.js`·저장소에 넣은 D3가 정적 파일을 돌려주고, 그 응답에 `Cache-Control: no-cache`가 있으며 같은 파일을 `If-None-Match`로 다시 물으면 `304`이고(H5), 조회 API 경로가 정적 파일 연결에 가려지지 않음을 확인한다.
- 화면 동작(그리기, 접고 펴기, 해시 상태)은 자동 테스트 도구를 두지 않고, 실제 서버를 띄워 브라우저로 확인한 결과를 완료 기록에 남긴다. 화면이 커지면 브라우저 자동 테스트를 설계한다.

## 7. 세션 개요 띠와 이동 배지

[시각화 인코딩 설계](VisualEncoding.md)의 E1 개요 띠와 E3 이동 배지를 세션 전체 흐름 상자에 둔다(M8-T1). 개요 띠는 세션의 **턴 시퀀스**다(I37). 인코딩의 근거와 버린 안(도구 호출마다 막대를 그린 띠)은 그 문서의 [E1](VisualEncoding.md#31-e1-개요-띠)과 [E3](VisualEncoding.md#33-e3-이동-배지)에 있다. 이 절은 구현 규칙을 정한다. 코드는 [src/agentvis/web/overview.js](../../src/agentvis/web/overview.js)다.

### 7.1 턴 요약

세션 상세 응답(`GET /api/sessions/{id}`)의 턴들에서 화면이 직접 계산한다. 새 API는 만들지 않는다. 턴마다 다음 값을 만든다.

| 값 | 계산 |
| --- | --- |
| 순번, 지시 첫 줄, 상태, 도구 호출 수, 실패 수 | 턴의 `index`, `prompt`, `state`, `tool_call_count`, `failure_count` |
| 실패 턴인지 | 실패 수가 0보다 크거나 상태가 `failed` |
| 첫 실패 단계 | 주 에이전트 단계 중 상태가 `error`·`interrupted`인 첫 도구 호출의 `id` |
| 작업 중 사용자 메시지 수 | `user_message` 단계 수 |
| 압축 수 | `compact` 단계 수 |
| 걸린 시간 | `ended_at`(없으면 마지막 단계의 `at`) − `started_at` |

실패 수는 세션 정보 상자의 실패 수와 같은 범위(주 에이전트의 도구 호출)를 센다.

### 7.2 배치

```text
 ◆                       압축┆              ◆                      ← 기호 줄
 [#1][#2 ✕2][#3][#4][#5][#6] ┆ [#7][#8 ✕1][#9][#10][#11 ✕6][#12]   ← 턴 칸
 턴 너비: [같게 | 걸린 시간에 비례]   #8 · 테스트 고쳐 · 도구 24 · 실패 1 · 4분 12초
```

- **턴 칸**: 턴마다 높이 28px의 칸 하나를 차례로 놓고, 칸 사이에 2px을 띈다. 칸 너비는 기본이 같은 너비(띠 너비 ÷ 턴 수)이고, 전환하면 걸린 시간에 비례한다(최소 6px).
- **색**: 실패 턴은 빨강 칸이고 칸 안에 `✕실패 수`를 쓴다. 나머지 턴은 회색 칸이다. 실행 중인 턴은 파랑 점선 테두리다. 색만으로 구분하지 않도록 ✕ 글자를 함께 쓴다([색과 접근성](../research/VisualizationPrinciples.md#49-색과-접근성)).
- **글자**: 칸 너비가 28px 이상이면 칸 안에 `#순번`을 쓰고, 실패 턴은 그 뒤에 `✕개수`를 쓴다. 좁으면 글자를 빼고 마우스를 올려 본다.
- **기호 줄**: 작업 중 사용자 메시지가 있는 턴의 칸 위에 노란 ◆를 둔다(흐름 그래프와 같은 모양, I39). 대화 요약(문맥 압축)이 일어난 턴은 칸 왼쪽에 점선 세로선과 "대화 요약" 글자를 둔다.
- **고른 턴**: 파랑 굵은 테두리.
- 띠 아래 한 줄에 마우스를 올린(없으면 고른) 턴의 순번, 턴 시작 지시의 첫 줄, 도구 호출 수, 실패 수, 걸린 시간, 작업 중 사용자 메시지 수를 적는다.

### 7.3 이동 배지

띠 위에 배지를 둔다: `실패한 턴 3 ◀ ▶`, `작업 중 사용자 메시지가 있는 턴 2 ◀ ▶`, `대화 요약이 일어난 턴 1 ◀ ▶`. 배지와 기호에 마우스를 올리면 대화 요약의 뜻("대화가 길어져 Claude Code가 앞 대화를 요약문으로 바꾼 턴. 이 뒤로 에이전트는 앞의 세부 내용을 요약으로만 기억합니다")이 나온다.

- ▶는 고른 턴보다 뒤에 있는 그 종류의 첫 턴을, ◀는 앞에 있는 마지막 턴을 고른다. 고른 턴이 없으면 ▶는 첫 턴, ◀는 마지막 턴이다. 개수가 0이면 단추를 끈다.
- **실패한 턴**으로 가면 그 턴의 첫 실패 단계도 고른다. 흐름 그래프는 그 노드를 고른 상태로 열고, 목록은 그 단계를 강조한다(7.5절).
- 단축키: `]` 다음 실패한 턴, `[` 이전 실패한 턴. 입력 칸이나 선택 상자에 초점이 있으면 동작하지 않는다.

### 7.4 상호작용과 상태

| 동작 | 결과 |
| --- | --- |
| 턴 칸을 누름 | 그 턴을 고르고, 고른 단계를 지운다 |
| 배지 ◀ ▶, `[` `]` | 7.3의 규칙으로 턴(과 첫 실패 단계)을 고른다 |
| 턴 너비 전환 | 같은 너비와 걸린 시간 비례를 바꾼다 |

- 해시 상태: `turn`(고른 턴), `step`(고른 단계 `id`), `width`(`time`이면 걸린 시간 비례).
- 처음 만든 안의 범위 고르기(`from`·`to`)와 순서·실제 시간 축(`axis`)은 뺐다. 턴 상자가 턴 하나만 보여 주므로 여러 턴에 걸친 범위는 아래 보기에 쓸 곳이 없고, 턴 안의 시간은 흐름 그래프의 시간축이 맡는다.
- 해시에서 프로젝트·세션이 바뀌지 않았으면 세션 상세를 다시 받지 않고 마지막 응답으로 다시 그린다. 그래프 응답도 턴마다 기억한다. 새로고침 단추는 모두 다시 받는다. 배지로 연달아 이동할 때 매번 세션 전체를 다시 계산하지 않기 위해서다.

### 7.5 아래 보기 연결

개요 띠는 [세 층](VisualEncoding.md#2-화면-구성)의 집계 층이고, 턴 상자의 흐름 그래프와 단계 목록은 원본 층이다.

- **턴 고르기**: 개요 띠와 턴 선택 상자는 같은 `turn`을 바꾼다. 어느 쪽에서 골라도 둘이 함께 바뀐다.
- **목록 보기**: 고른 턴의 단계를 늘어놓고, 고른 단계가 있으면 강조(파랑 테두리)한 뒤 화면 안으로 스크롤한다.
- **흐름 그래프**: 고른 턴의 그래프를 그리고, 고른 단계가 있으면 그 노드를 고른 상태로 시작한다(노드 상세가 열린다). 노드 `id`는 단계 `id`이므로([그래프 모델의 노드](FlowGraph.md#32-노드)) 그대로 찾는다.
- 턴 선택 상자에서 다른 턴을 고르면 고른 단계를 지운다.
