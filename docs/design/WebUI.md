# 웹 UI 설계

이 문서는 AgentVis의 웹 화면(`src/agentvis/web/`)을 설계한다. 화면이 보여 주는 데이터는 [분석기 설계](Analysis.md)의 조회 API가 주고, 화면이 답해야 할 질문은 [제품 비전의 핵심 분석 질문](../ProductVision.md#2-핵심-분석-질문)에 있다. 관련 태스크는 [로드맵](../Roadmap.md#m4-실시간-웹-ui)의 M4-T2~M4-T5다. 전체 문서 목록은 [문서 인덱스](../index.md)에서 확인한다.

2026-10-31 사용자 방침: "보면서 나중에 추가하고 고치면 된다." 이 문서는 첫 화면을 만들기 위한 권장안이며, 화면을 보고 고친다.

## 1. 기술과 라이브러리

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 화면 기술 | 빌드 단계 없는 HTML·CSS·JavaScript(ES 모듈) | [시스템 구조의 기술 선택](../Architecture.md#6-기술-선택)대로 도구 체인을 늘리지 않는다. |
| 시각화 라이브러리 | 첫 화면(목록)은 쓰지 않는다. [작업 흐름 그래프](FlowGraph.md)는 **D3**를 쓴다. | 목록은 CSS 세로 타임라인으로 충분하다. 그래프는 시간축 척도, 확대·이동, 곡선 간선이 필요하고, D3는 이를 세밀하게 제어할 수 있는 표준 도구다. 라이브러리는 [1.1절](#11-저장소에-넣은-라이브러리)대로 저장소에 넣어 쓴다. |
| 제공 방식 | 서버 앱이 `web/` 폴더를 정적 파일로 제공한다. `GET /`는 `index.html`이다. | 별도 웹 서버 없이 `agentvis serve` 하나로 쓴다. |
| 갱신 | 첫 화면은 "새로고침" 버튼으로 다시 불러온다. 실시간 갱신은 M4-T2(SSE)에서 붙인다. | |

### 1.1 저장소에 넣은 라이브러리

화면이 쓰는 외부 라이브러리는 **외부 CDN에서 받지 않고, 파일을 저장소의 `src/agentvis/web/vendor/`에 넣어 우리 서버가 제공한다.** CDN(Content Delivery Network)은 남이 운영하는 파일 배포 서버로, 화면을 열 때마다 브라우저가 그곳에서 라이브러리를 받아 온다. 2026-10-31에 사용자와 이 결정을 다시 검토했고(I24), 아래 이유로 유지한다.

| 기준 | 외부 CDN | 저장소에 넣기 |
| --- | --- | --- |
| 보안 | 화면에는 로컬 작업 기록 전체(명령, 파일 내용, 경로)가 올라온다. CDN의 파일이 바뀌거나 오염되면 그 스크립트가 이 내용을 읽어 밖으로 보낼 수 있다. 무결성 해시(SRI)로 줄일 수는 있다. | 저장소에 커밋해 검토한 파일만 실행된다. |
| 오프라인 | 인터넷이 없으면 화면이 깨진다. | 항상 동작한다. |
| 재현성 | 같은 주소의 내용이 바뀔 수 있다. | 커밋한 버전 그대로다. |
| 비용 | 없음 | 파일 하나(수백 KB)를 저장소에 두고, 판올림을 직접 한다. |

**넣는 절차**
1. 공식 배포처(npm 레지스트리의 패키지 압축 파일)에서 정확한 버전을 받는다. 받은 압축 파일을 레지스트리가 공개한 무결성 값(`dist.integrity`, SHA-512)과 대조한다.
2. 화면이 쓰는 배포 파일(예: `dist/d3.min.js`)과 라이선스 파일만 `vendor/`에 `<이름>-<버전>.<확장자>`, `LICENSE-<이름>.txt`로 둔다. 파일 내용은 고치지 않는다. git이 줄바꿈을 바꾸지 않도록 `.gitattributes`에서 `vendor/`를 `-text`로 둔다([운영체제 이식성](../CodeRule.md#31-운영체제-이식성)).
3. 아래 표에 파일, 버전, 라이선스, 출처, SHA-256을 적는다. 판올림할 때도 같은 절차를 밟고 표를 고친다.
4. `index.html`에서 `app.js`보다 먼저 일반 `<script>`로 불러온다. D3의 배포 파일은 전역 변수 `d3`를 만든다.

**넣은 라이브러리**

| 파일 | 라이브러리 | 버전 | 라이선스 | 출처 | SHA-256 |
| --- | --- | --- | --- | --- | --- |
| [d3-7.9.0.min.js](../../src/agentvis/web/vendor/d3-7.9.0.min.js) | D3 | 7.9.0 | ISC ([LICENSE-d3.txt](../../src/agentvis/web/vendor/LICENSE-d3.txt)) | npm `d3@7.9.0` `dist/d3.min.js` | `f2094bbf6141b359722c4fe454eb6c4b0f0e42cc10cc7af921fc158fceb86539` |

2026-10-31 M4-T8: `https://registry.npmjs.org/d3/-/d3-7.9.0.tgz`의 SHA-512가 레지스트리의 `dist.integrity`와 같음을 확인했다.

[웹 정적 파일 검사기](../VerificationTools.md#10-웹-정적-파일-검사기)가 이 절의 규칙 중 기계적으로 확인할 수 있는 부분을 검사한다.
- `vendor/`의 모든 파일이 이 표에 있고, 그 SHA-256이 표와 같은가
- 우리가 쓴 화면 파일에 외부 주소가 없는가

## 2. 화면 구성

세 영역을 가로로 놓는다. 화면이 좁으면 위아래로 쌓는다.

```text
┌──────────────┬──────────────────────┬───────────────────────────────────────────────┐
│ 프로젝트     │ 세션                 │ 세션 상세                         [새로고침]  │
│              │                      │ 일단 먼저 우리는 문서 규칙부터…  턴 51 · 실패 15 │
│ ▸ AgentVis   │ ▸ 일단 먼저 우리는…  │ ───────────────────────────────────────────── │
│   ~/Desktop/ │   10-31 04:41        │ ▾ #2 코드 작업 규칙 문서도 만들어라…  ✕2  ended │
│   세션 1     │   턴 51 · 실패 15    │   ◦ 생각 (접힘)                                │
│ ▸ ProjInit   │                      │   ▪ Write docs/CodeRule.md            ✓       │
│ ▸ AI윤리     │                      │   ▪ Bash python3 -m tools.check_docs  ✕ 오류   │
│   …          │                      │   ★ 사용자: 파이썬은 무조건 uv 환경에서 써라. │
│              │                      │   ▪ Bash uv init …                    ✓       │
│              │                      │ ▸ #3 …                                         │
└──────────────┴──────────────────────┴───────────────────────────────────────────────┘
```

- **프로젝트**(`GET /api/projects`): 이름, 상위 경로, 세션 수, 마지막 활동. 폴더가 없는 프로젝트는 흐리게 표시한다. 목록에 없는 폴더의 경로 직접 입력은 M4-T5에서 더한다.
- **세션**(`GET /api/sessions?project=…`): 제목, 마지막 활동, 턴 수, 도구 호출 수, 실패 수(0보다 크면 강조).
- **세션 상세**(`GET /api/sessions/{id}`): 턴 목록. 턴은 접고 펼 수 있으며, 처음에는 실패가 있거나 진행 중인 턴과 마지막 턴만 펼친다.
- 선택 상태(프로젝트, 세션)는 URL의 해시(`#project=…&session=…`)에 둔다. 새로고침하거나 주소를 공유해도 같은 화면이 열린다.
- 세션 상세에는 이 문서의 목록 보기와 함께 턴별 [작업 흐름 그래프](FlowGraph.md#6-화면) 보기를 둔다(M4-T8).

## 3. 턴과 단계 표시

**턴 머리**: 순번, 사람이 입력한 지시(첫 줄, 펼치면 전체), 상태(`running`·`ended`·`failed`), 도구 호출 수, 실패 수, 시작 시각.

**단계**: [분석기 설계의 단계 종류](Analysis.md#4-단계)마다 표시를 정한다. 단계는 시간순 세로 타임라인이며, 색과 기호로 종류와 상태를 구분한다.

| 단계 | 표시 |
| --- | --- |
| `thinking` | 흐린 글씨, 기본은 접힘(첫 줄만). 펼치면 전문. |
| `text` | 모델 응답. 기본 글씨. 길면 일부만 보이고 펼친다. |
| `tool_call` | 도구 이름 + 입력 요약(Bash는 `command`, 파일 도구는 `file_path`, 그 밖은 입력 JSON 앞부분) + 상태 기호. 펼치면 입력 전체, 결과, 오류, 실행 시간, 권한 요청 여부. 서브에이전트가 있으면 그 단계들을 들여써서 펼친다. |
| `user_message` | **강하게 강조**(눈에 띄는 배경). 작업 도중 사람이 보낸 메시지로, 지시 오해(Q6)를 볼 때 가장 중요한 지점이다. |
| `notification` | 흐린 한 줄(출처: 작업 알림, 하위 에이전트 보고, 사용자 셸 명령). 펼치면 전문. |
| `hook_failure` | 경고 색 한 줄. "이 구간의 hook 수집이 빠짐". |
| `compact` | 가로 구분선 "문맥 압축". |
| `subagent` | 연결되지 않은 서브에이전트. 들여쓴 단계 묶음. |

**도구 호출 상태 기호와 색**

| 상태 | 기호 | 색 |
| --- | --- | --- |
| `success` | ✓ | 초록 |
| `error` | ✕ | 빨강 |
| `interrupted` | ⏸ | 주황 |
| `running` | ● | 파랑 |
| `unfinished` | ? | 회색(권한 거부·중단의 후보) |

## 4. 보안

- 세션 기록의 모든 텍스트는 신뢰할 수 없는 데이터다(다른 웹 페이지 내용, 명령 출력 등이 들어 있다). 화면에 넣을 때는 항상 `textContent`로 넣고 `innerHTML`을 쓰지 않는다. 저장된 텍스트가 스크립트로 실행되는 것(XSS)을 막기 위해서다.
- 화면은 같은 서버의 조회 API와 정적 파일만 `GET`으로 부른다. 외부 주소로 요청하지 않는다(외부 CDN, 글꼴 포함). 라이브러리는 [1.1절](#11-저장소에-넣은-라이브러리)대로 저장소에 넣어 쓴다.
- 모든 요청은 서버의 [요청 검증](Collector.md#21-요청-검증) `Host` 검사를 받는다. 화면은 `http://127.0.0.1:<포트>/` 또는 `http://localhost:<포트>/`로 연다.

## 5. 파일 구성

| 파일 | 내용 |
| --- | --- |
| [src/agentvis/web/index.html](../../src/agentvis/web/index.html) | 화면 뼈대 |
| [src/agentvis/web/app.js](../../src/agentvis/web/app.js) | 조회 API 호출, 화면 그리기, 해시 상태 |
| [src/agentvis/web/style.css](../../src/agentvis/web/style.css) | 배치, 단계 종류·상태 색, 밝은·어두운 테마(`prefers-color-scheme`) |
| `src/agentvis/web/graph.js` | 작업 흐름 그래프 그리기([작업 흐름 그래프 설계의 화면](FlowGraph.md#6-화면)) |
| `src/agentvis/web/vendor/` | 저장소에 넣은 외부 라이브러리([1.1절](#11-저장소에-넣은-라이브러리)) |

[서버 앱](../../src/agentvis/server.py#create_app)은 조회 API 경로를 먼저 등록하고 마지막에 `web/`를 `/`에 정적 파일로 연결한다. 정적 파일 연결은 [수집기 설계의 서버 앱](Collector.md#2-http-엔드포인트)에 더한다. 화면 코드는 Python이 아니므로 포인터 커버리지 검사 대상이 아니며, 이 문서가 파일 단위로 가리킨다.

## 6. 테스트

- [tests/test_api.py](../../tests/test_api.py)에서 `TestClient`로 `GET /`가 `index.html`을, `/app.js`·`/style.css`·`/graph.js`·저장소에 넣은 D3가 정적 파일을 돌려주고, 조회 API 경로가 정적 파일 연결에 가려지지 않음을 확인한다.
- 화면 동작(그리기, 접고 펴기, 해시 상태)은 자동 테스트 도구를 두지 않고, 실제 서버를 띄워 브라우저로 확인한 결과를 완료 기록에 남긴다. 화면이 커지면 브라우저 자동 테스트를 설계한다.
